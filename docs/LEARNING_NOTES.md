# 実装と復習のメモ

実装内容と学習候補を、将来の復習・記事・面接説明に使える形で整理する。記載されているだけで理解済みとは扱わず、説明に使う前にコードと動作を再確認する。

## Djangoのセッション認証

ログインに成功すると、Djangoは推測しにくいセッションキーを発行する。ブラウザのCookieへ保存するのはパスワードやメールアドレスではなく、このセッションキーである。以後のAPIリクエストではCookieが自動送信され、Djangoがセッションキーから利用者を特定して`request.user`へ設定する。

ログアウト時はDjango側のセッションを無効化する。ブラウザ側で表示だけを未ログインへ変える方法では、サーバー上のログイン状態が残るため不十分である。

## セッション認証とCSRF対策

Cookieはブラウザから自動送信されるため、別の悪意あるページから意図しない変更リクエストを送られる可能性がある。CSRF対策では、Djangoが発行したトークンをReactが`X-CSRFToken`ヘッダーへ設定し、Cookieとトークンの組み合わせが正しい場合だけ新規登録、ログイン、ログアウトなどの変更操作を受け付ける。

開発中は`localhost:5173`と`127.0.0.1:5173`を別のオリジンとして扱う点にも注意する。利用中のURLが`CSRF_TRUSTED_ORIGINS`にない場合、正しいトークンを送ってもDjangoはリクエストを拒否する。

## メールアドレスの大文字・小文字

入力されたメールアドレスの表記は保持しながら、ログイン検索と重複確認では大文字・小文字を区別しない。画面上の事前確認だけでは同時登録を完全に防げないため、PostgreSQLにも小文字化したメールアドレスの一意制約を設定する。

## ログイン試行回数の制限

ログインAPIは1分間に10回、新規登録APIは1時間に5回までとし、短時間の総当たりと大量登録を抑える。初期版はDjangoのキャッシュを利用する軽量な制限であり、複数サーバーへ拡張する場合は共有キャッシュを利用する。

送信元の判定で`X-Forwarded-For`を無条件に信用すると、利用者がヘッダーの値を変えて制限を回避できる。ローカル開発では`NUM_PROXIES=0`として`REMOTE_ADDR`を使用し、Cloud Runへ配置するときは実際に信頼できるプロキシの構成を確認してから値を変更する。

## ログアウトを何度実行しても安全にする

セッションの有効期限切れや別タブでのログアウト後でも、ログアウトAPIは成功として扱う。すでにログアウト済みの状態をもう一度ログアウトしても結果が変わらないため、画面とサーバーの状態がずれにくくなる。このように同じ操作を複数回実行しても結果が変わらない性質を「冪等性」という。

## 記録予定

- Web Audio APIでブラウンノイズを生成する仕組み
- 長い休憩用音源をWeb Audio APIへ全展開せず、音声要素で再生する理由
- ブラウザのタイマーがバックグラウンドで制限される理由
- 1秒ずつ減算せず、時刻の差から残り時間を計算する理由
- PWAと通常のWebアプリの違い
- Django認証でパスワードを安全に扱う仕組み
- 独自ユーザーモデルを最初に作る理由と`AbstractUser`の継承
- ReactとDjango REST APIの役割分担
- PostgreSQLだけをDockerで動かし、ReactとDjangoをMac上で動かす開発構成
- PostgreSQLから当日・累計の学習時間と日別履歴を取得する方法
- 学習記録と振り返りを利用者ごとに分離する方法
- WebページやPWAから現在のウィンドウを確実に自動終了できない理由

## コード読解で理解が曖昧なため、完成後に復習する候補

- Reactで関数をpropsとして複数のコンポーネントへ渡し、必要な操作時に呼び出す流れ
- 関数そのものを渡す書き方と、その場で関数を実行する書き方の違い
- `Promise`、`async`、`await`、`.then()`、`.catch()`、`.finally()`の関係
- 非同期処理の先頭へ`void`を付ける理由と、捨てている戻り値
- `useEffect`が実行される時期、依存配列、後片付け関数の役割
- 通信中に画面が消えた場合、`isActive`でstateの更新を止める理由
- TypeScriptの型の中に別の型や配列が含まれる構造の読み方
- Djangoへ保存したデータと、Reactのstateへ保持した表示用データの違い

## 技術記事にする場合の候補と目次案

### ReactでAPI関数をpropsとして渡す流れ

1. API通信用関数を定義する
2. 親コンポーネントから関数そのものをpropsで渡す
3. 子コンポーネントで別名のpropsとして受け取る
4. クリックや画面表示をきっかけに関数を実行する
5. 関数を渡す方法がテストや責務の分離にどう役立つか

### Reactの非同期処理で使うPromiseとvoid

1. `Promise`が表すもの
2. `async`と`await`を使う書き方
3. `.then()`、`.catch()`、`.finally()`を使う書き方
4. 非同期処理の先頭にある`void`の意味
5. エラーを未処理のままにしないための注意点

### useEffectによる初回データ取得と後片付け

1. 履歴画面の表示後にAPIを呼ぶ流れ
2. 依存配列に関数を指定する意味
3. 通信結果をstateへ保存すると画面が更新される仕組み
4. 後片付け関数が実行される時期
5. 画面を閉じた後のstate更新を防ぐ方法

### PostgreSQLだけをDockerで動かす開発構成

1. React、Django、PostgreSQLがそれぞれどこで動いているか
2. PostgreSQLだけをコンテナ化する理由
3. `venv`、Django開発サーバー、Vite開発サーバーの役割
4. 開発環境をすべてDocker化する場合のメリットと追加設定
5. ローカル開発用構成とCloud Run向け本番構成を分ける理由
